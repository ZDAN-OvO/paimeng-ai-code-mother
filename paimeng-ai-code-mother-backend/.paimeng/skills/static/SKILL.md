# 静态页面交付

## 适用判断

- 用户要求 HTML/CSS/JS、单页、无构建，或现有目录没有 `package.json` 时使用本技能。
- 用户明确要求 Vue/React，或现有 `package.json` 已使用框架时，不要用本技能，改用对应技能。
- 不确定时先 `ls` / `read`，按现有项目事实决定，不要擅自引入构建链。

## 平台边界

- 平台直接服务源码目录，不安装依赖、不执行构建；入口必须是根目录的 `index.html`。
- 只写源码：不要创建 `package.json`、锁文件、`node_modules`、`dist`、`.npmrc` 或 Vite 配置。
- 资源全部使用本地相对路径；预览环境没有外网，禁止 CDN、远程字体、远程图片和在线接口。
- 文件工具路径相对于项目根目录；写或改之前先 `read`；`edit` 的 `oldText` 必须唯一匹配；删除目录前先 `ls` 并核对 `version`。
- 不要运行命令、不要启动服务器；平台负责自动刷新和预览。
- 写完文件后直接结束本回合，不要轮询 `preview status` 或等待预览启动；平台会在模型回合结束后验证。

## 工作流

1. 侦察：用 `ls` / `read` 查看现有文件，确认入口、样式、脚本和已有交互。
2. 设计：确定最小文件集，通常为 `index.html`、`styles.css`、`app.js`；优先保持已有结构，小改动不要重写全站。
3. 实现：先写或改结构，再补样式和交互；所有 `href` / `src` 必须指向真实存在的本地文件。
4. 自检：入口存在、引用无 404、按钮/表单/切换有真实行为、窄屏可用、没有 TODO 或占位内容。
5. 交付：用中文说明改了哪些文件、如何验证；不要声称平台验证已通过。

## 质量原则

- 使用语义化 HTML，键盘可操作，表单有 `label`，图片有 `alt`。
- 交互用原生 JavaScript，状态变化直接反映 DOM；避免空按钮和假交互。
- 样式集中管理，不要把大段内联样式复制到多个文件。
- 保持用户已有内容和结构，除非用户明确要求重做。

## 常见修复

- 平台提示缺少 `index.html`：在根目录创建入口，不要放到子目录。
- 预览空白：检查相对路径、脚本是否在 DOM 之后加载、浏览器控制台是否有语法错误。
- 用户要求 Vue/React：停止静态实现，加载对应技能，并通过 `dependencies` 工具添加依赖。
