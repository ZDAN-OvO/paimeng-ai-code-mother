**原有 13 条路径都有对应原型入口，但新增的 Agent 流程还没补齐。**
优先缺口是 Todo、Plan 审阅、验证修复与完成状态。
版本触发、Skill 使用路径与 Design 定位载荷也需对齐。

本页只报告差异，不修改产品代码或契约。
没有启动服务器，也没有浏览器点击或录屏验证。
“有原型”只表示源码存在入口与交互，不代表 MVP 已完成。

## A 原有 13 条路径：大部分形态已表达

| #   | 契约             | 原型覆盖                                       | 仍需区分的边界                               |
| --- | ---------------- | ---------------------------------------------- | -------------------------------------------- |
| 1   | 一句话建项目     | 首页发送后创建 Project、首个 Chat 并进入工作区 | 数据写入 localStorage                        |
| 2   | 流式对话         | 打字、工具卡、折叠过程与停止按钮               | 定时脚本，不是模型流；终止状态不完整         |
| 3   | 多文件项目       | 文件内容为真实字符串，后续轮修改文件           | 构建成功为预设输出，没有实际编译             |
| 4   | 代码面板         | 目录、只读代码、行号、着色与复制               | 生成中树与正文采用不同数据源                 |

| 13  | 环境变量         | 增删、编辑、键名校验、掩码与保存               | 不重启 Sandbox，也不注入发布实例             |

## B 优先补齐：新增 Agent 流程缺口

优先级表示接口实现前应先定清的顺序，不是线上故障等级。

| 优先级 | 差异               | 当前原型                                      | 应表达的状态                                           |
| ------ | ------------------ | --------------------------------------------- | ------------------------------------------------------ |
| P1     | Todo 缺失          | 无任务清单，也无 Todo message part            | 待处理、进行中、完成；取消不假报完成                   |
| P1     | Plan 缺失          | “先规划”仍进入普通生成脚本                    | 只读规划、待审阅、批准、要求修改、拒绝                 |
| P1     | 验证修复缺失       | 固定显示 build 成功                           | 检查失败、错误返回、修复、重跑检查                     |
| P1     | 完成判定缺失       | 没有可达的 verify_project／complete_task 场景 | 缺证据拒绝完成，修改后旧证据失效                       |
| P1     | 顶层终止状态不完整 | 非 streaming 就显示绿色“已完成”               | 成功、失败、已停止、预算耗尽、等待用户                 |
| P2     | 八项工具演示未补齐 | 已有通用工具卡渲染，但脚本只覆盖旧工具子集    | 补 Read／Edit／Glob／Grep／Move／Delete 场景及失败反馈 |

这是信息结构与可演示流程的缺口，不需要先接真实模型才能表达。
Plan 审阅也不能由普通 ask_user 提问替代。
执行器的真实权限校验留在实现阶段，原型先表达拒绝状态。

## C 明确的行为差异：版本与 Design 载荷

### 版本：正常生成与回滚符合，调研路径不符合

当前契约仍是每条助手消息结束后记录 Version。
纯调研助手消息只结束 streaming，没有追加 Version。
这不是建议对齐 v0；应按已决定的源码 Snapshot 规则处理。

停止生成时会清掉 liveFiles／liveSite，并说明没有产生新版本。
这没有表达“保留未完成工作”的要求。
取消、异常的恢复边界仍需细化，不能直接以成功状态结束。

证据：

- [调研结束路径](../../src/prototype/store.tsx:274)
- [调研分支提前返回](../../src/prototype/store.tsx:347)
- [停止与正常保存版本](../../src/prototype/store.tsx:466)
- [当前版本与异常边界](../architecture.md:212)

### Design：选中位置在界面可见，但发送时丢失

选择回调拿到 component 与 src，却只把 label 填进草稿。
发送只传 text 与 images，随后清掉 selection。
消息没有携带文件、组件与位置，后端无法可靠知道选中了哪段源码。

data-src 替代 fiber 是已声明的 mock，不作为缺陷。
真正差异是选中上下文没有进入拟定的消息契约。

## D Skill：有管理页，缺“加载并使用”的演示

| 差异       | 现状                                                                        | 对齐方向                                                      |
| ---------- | --------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 首批清单   | 有 frontend-design、shadcn-ui、nextjs-app-router、web-search、skill-creator | 对齐 nextjs／shadcn 标识，补 debug-and-verify，或明确别名映射 |
| 加载入口   | load_skill 只预留卡片外观，生成脚本没有使用技能状态                         | 展示 description 路由、正文与 references 的按需读取           |
| 导入后使用 | 管理页能导入、启用与切换 Trust                                              | 补“导入后下一轮实际选择此技能”的可达场景                      |
| 文件清单   | 导入页预览多文件，store 实际只保留 SKILL.md                                 | 清单与保存结果一致，避免提前锁错 API                          |
| 来源标识   | 分 builtin／user 展示，操作只按 slug                                        | 使用稳定来源标识，区分同名而非静默混用                        |
| 信任限制   | 有勾选状态，没有可达的脚本拒绝场景                                          | 演示未信任脚本被拒绝，Trust 不扩大权限                        |

上述是原型状态与交互缺口，不要求本轮实现磁盘导入。
AI 与 Agent 领域 Skill 已排在 MVP 后，不算当前遗漏。

## E 文档待同步：不能直接判原型越界

原型改造 brief 记录了另一轮已确认设计。
主文档与 brief 有差异，应先明确当前口径，不直接删除入口。

| 项目               | 原型与 brief                             | 主契约对照                                   |
| ------------------ | ---------------------------------------- | -------------------------------------------- |
| 日志面板           | 六个右栏面板之一，有明确 mock 标记       | 架构仍写不提供 logs 面板，需要同步或区分术语 |
| 产物与发布记录     | 展示文件统计、快照与发布历史             | 不等于已排除的通用制品平台                   |
| Template 画廊      | 内置完整示例的结构与视觉预览             | 不等于公开用户模板市场，宜补充定义           |
| 明暗主题           | 跟随系统或手选，状态写本地               | 属已记录原型要求，主文档未逐项展开           |
| 语音输入           | 使用浏览器 SpeechRecognition，失败时提示 | 不是后端 ASR，主文档尚未展开                 |
| Database／Terminal | 菜单显示未接通，不创建实际面板           | 不能算已实现，也不等于开放终端能力           |

## F 待真实接入：不要混成 UI 缺口

| 层               | 当前证据                         | 实现阶段的工作                                |
| ---------------- | -------------------------------- | --------------------------------------------- |
| 持久化           | localStorage，数据库有表定义     | Project／Chat／Message 等接口与真实持久化     |
| Agent            | 定时脚本拼接文字与工具结果       | 模型调用、AI SDK 消息流、工具执行与预算       |
| Sandbox／Preview | 本地 MockSite 与文件字符串       | Docker 工作区、依赖、next dev、HMR 代理与回收 |
| Version          | 浏览器内 files／site 快照与 diff | 宿主源码 Snapshot、恢复与版本存储             |
| Deploy           | 本地记录、定时构建步骤           | 沙箱构建、standalone、runner 与跨浏览器访问   |
| 环境变量         | 编辑和掩码存在，值写浏览器存储   | 脱敏接口、重启语义、Sandbox 与 runner 注入    |
| 搜索／抓取       | 固定工具卡与示例结果             | 真实服务调用、网络限制与引用来源              |
| Skill            | 本地索引、文件名与信任状态       | 正文读取、目录导入、受控制作与脚本执行        |

当前 src/server 仅有 db 与 id 模块，API 仅 health 路由。
有表定义不能证明这些流程已经接通。
原型的“已写入磁盘”“保存并重启”等文案不能充当执行证据。
接入前应标明模拟状态，不将 localStorage 当作生产密钥保存方案。

原型 README 的拟定接口也需同步新增 Todo／Plan、审批恢复与完成状态。
它目前主要覆盖旧 Part 集合，不应直接冻结为后端最终协议。
AI SDK 的消息流适配应在实现时验证，不在本报告推断其兼容性。

## G 先补什么，哪些仍需实测？

建议先补 B 节的流程状态，再对齐版本、Skill 与 Design 的消息契约。
随后同步 E 节文档口径，最后按既定里程碑接真实后端。
这是建议，不是已经开始实施。

另有两项源码疑点需浏览器核实：

- 代码正文与文件数读取 liveFiles，文件树却读取 viewed.files。
- Template 预览的 iteration／brand 未完整传入新建起点。

前者在生成中可能出现文件树落后于正文的演示不一致。
后者需确认“使用这个模板”后是否保留用户刚看到的外观。
本轮没有浏览器实测，不将两项列为已复现缺陷。
