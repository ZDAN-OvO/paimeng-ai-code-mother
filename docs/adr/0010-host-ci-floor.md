# 0010 宿主底线：CI 每轮必跑，没有通过记录不能标成功

- 状态：已接受
- 日期：2026-11-09

## 背景

是否调用 review、调用哪一种，交给主 agent 判断（ADR 0013）。主 agent 也可能把大改动判成小改动，或者在没检查的情况下宣布完成。模型停止调用工具、Todo 全部勾完、达到最大步数，都会出现在任务其实没做完的时候。需要一条不依赖模型判断的底线。

可选做法：

1. 全部交给主 agent，宿主不设底线。
2. 宿主固定流程：每轮依次跑 CI、code review、completion review。
3. 宿主只守确定性检查：CI 每轮必跑，结果绑定源码修订；review 由主 agent 决定。

## 结论

选 3。每轮结束前宿主跑一次 CI（类型检查、lint、构建、HTTP 就绪），结果绑定当前源码修订；当前修订没有通过记录，宿主拒绝成功状态，把失败送回主 agent。写入、编辑、移动、复制、删除使受影响的旧记录失效。只有 CI，没有 CD：发布仍由用户触发。

## 后果

- 方案 2 让每次小改动都付两次 review 的成本，而且 code review 与 completion review 不是一对一关系，因此不采用。
- 主 agent 没调用 completion review 就收尾、且 CI 通过时，本轮算成功，但记为「未经完成审查」，界面可见，评测计入漏审率。
- CI 通过只证明对应的确定性事实，不证明视觉、交互或需求被满足。
- 检查失败、预算耗尽、取消与运行异常如实呈现并保留工作；中断按 ADR 0002 处理。
