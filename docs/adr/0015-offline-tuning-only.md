# 0015 只做离线调优，结果以 PR 交付

- 状态：已接受
- 日期：2026-11-09

## 背景

主 agent、两个 review agent 的提示词、打回上限与模型选择需要持续调整。调整可以自动化，问题是用什么数据、改动怎么生效。

可选做法：

1. 上线后自动调优：用真实用户的对话与返工行为，直接改线上配置。
2. 离线自动调优：夜间在用例集上提改动、跑对比，只保留在保留集上也变好的版本，开 PR 等人审。
3. 只做人工调优：每次由人提改动、看对比。

## 结论

选 2。调优在本机定时运行，密钥留在本机，候选改动只在调优集上筛选，保留集只在决定能否合入时使用；每轮有 token 与候选数熔断，超限停下报告。产出是开到新分支的 PR，附指标前后对比与花费，由用户审核合入。

## 后果

- 方案 1 与 ADR 0007 冲突：开源项目各自部署，数据在各自机器上，没有汇总的线上数据，还要处理隐私与自动回退，因此不采用。交付后的返工率只做人工观察。
- 方案 3 保留为起步：反思式优化先手工跑两三轮，再决定是否接入框架。
- 开 PR 的身份与每晚 token 上限是待定配置项，实现前确定。
- 保留集用过几次就要换新，否则也会被调优间接拟合。
