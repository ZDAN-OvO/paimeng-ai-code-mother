# Python 管理应用对话历史，Java 校验访问权限

Paimeng 的应用归属和访问权限由 Java 管理。Python 对话与 Agent 服务负责保存和查询用户可见的对话历史，作为这份数据的唯一来源。浏览器通过 Java 的历史接口查询，Java 按应用校验权限后，再通过内部接口向 Python 请求记录。

由 Java 处理访问授权，可以复用现有登录和应用权限逻辑。由 Python 持有历史，可以让对话和 Agent 上下文在同一个服务中维护。

Python 将会话和用户可见的消息存入 PostgreSQL，将 Agent 的对话记忆缓存在 Redis。聊天页和管理员的历史查询都以 PostgreSQL 中的消息为准。Redis 记忆丢失时，Python 从已保存的对话恢复上下文，Agent 可以读取当前项目文件后继续生成。

Python 在同一个 PostgreSQL 事务中保存消息并单调递增会话版本。提交后，用 Lua 校验 Redis 版本是否等于提交前的版本，匹配时追加消息并更新版本。重建时，先观察 Redis 是否缺失或记录其版本，再用一个 PostgreSQL `REPEATABLE READ READ ONLY` 事务读取会话版本和消息。Lua 回写先拒绝 Redis 当前版本高于快照版本的情况。其余情况仅在 Redis 状态仍等于观察状态，或 Redis 当前版本低于快照版本时回写。并发重建按任一顺序完成时，Redis 都保留较新的版本。回写失败时，Agent 使用 PG 快照继续执行。

聊天页按消息时间和消息 ID 组成的复合游标翻页。旧历史只有秒级时间，同秒消息按原 ID 确定顺序，避免仅用时间游标时跨页漏读。

首期每个应用只有一个会话，用户再次发送消息时继续使用同一个会话。正式切换前，将旧应用的完整用户可见历史迁入 Python，保留消息内容、发言者、时间和原有顺序。切换后，用户可以重新打开旧应用、翻看消息并继续发言。打开已有历史的应用时，系统不会再次发送创建应用时的初始提示词。

管理员继续通过现有管理页面查询全站对话历史。Java 校验管理员身份，Python 提供分页数据。

本次迁移以 Java 主线的现有产品功能为验收基线。迁移后继续支持三种生成模式、应用类型选择、旧项目续改、预览、下载和发布。用户刷新或关闭页面后，已经开始的生成继续运行。用户重新打开应用时，可以看到本轮仍在生成，或在同一个会话中看到已保存的结果。

Java 统一管理生成任务状态，并根据 Agent 执行结果和应用构建结果判定最终状态。Python 执行 Agent，并将 Java 确认的成功或失败结果按任务 ID 幂等写入对话历史。并发任务同步与事件流回放见 [ADR 0003](0003-decouple-task-submission-and-stream-replay.md)，临时目录隔离与构建自动修复闭环见 [ADR 0004](0004-python-isolated-workspace-and-build-repair-loop.md)。

文件不存在、参数不合法或待替换文本找不到等工具错误，由 Python 封装成与原调用对应的工具结果，返回给 Agent。Agent 可以根据错误内容调整后续操作。

服务端确认本轮已经无法继续执行时，Java 将任务标为失败，用户可以手动重试。
