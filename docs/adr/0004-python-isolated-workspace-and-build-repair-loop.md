# 临时目录隔离本轮改动，Python 闭环完成构建与自动修复

每次生成任务开始时，Java 从应用当前的正式项目目录复制一份本轮临时工作目录交给 Python（新应用为空目录），不让 Agent 直接修改正式目录，避免中途出错或构建失败破坏用户原有的项目与预览。

对于需要构建的项目类型（如 Vue / NPM 模式），Python 在本轮临时工作目录内完成「Agent 修改文件 → 执行构建 → 捕获并截断关键报错返回给 Agent 自动修复」的单向闭环，并将构建与修复过程实时推送给 Java 和前端。现有 Java 侧构建器只检查退出码而未捕获错误输出，改造后由 Python 侧执行构建并提取关键错误信息，避免整屏日志撑爆 Agent 上下文。

文件工具的路径校验不能限制 npm 生命周期脚本，因此安装和构建在受限容器中运行。容器只挂载本轮临时目录，不提供服务凭据和正式目录访问；受限构建环境不可用时，不在服务主机直接执行生成的项目脚本。构建完成后仍须检查产物中的符号链接或 junction，预览读取也校验最终真实路径，防止容器内产物经链接指向工作区外文件。

每个任务最多自动修复 2 次，共构建 3 次。失败候选直接幂等提交失败结果，保留正式目录和旧预览。成功候选由 Java 按 [ADR 0003](0003-decouple-task-submission-and-stream-replay.md) 取得交付权，再验收并切换临时目录。每次重命名前持久化交换阶段。

确认交换失败后，在同一 PG 事务保存 `RESTORING` 和失败结果载荷。已有旧目录时，根据正式目录和备份是否存在，继续恢复或确认恢复已完成。旧预览确认后再提交失败结果。新应用在正式目录和备份都不存在时直接提交已存失败结果。失败结果以持久化载荷为准，可跨重启幂等提交。恢复未完成时保持 `COMMITTING`，阻止下一任务。收到 `commit-result` 确认后才写终态并清理备份和临时目录。

相比「Java 保留构建逻辑并在外部循环调用 Python 重试」，本方案避免了 Java 与 Python 之间的双向循环调用，也避免了将多轮内部修复日志混入用户对话记录，任务状态机更清晰。代价是 Python 运行环境需要具备 Node.js 与 `npm` 能力（本地开发共用本机环境，容器部署时在 Python 镜像内提供 Node）。
