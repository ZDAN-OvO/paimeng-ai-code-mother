# 0011 Plan 是审批门，不是另一个 Agent

- 状态：已接受
- 日期：2026-11-08

## 背景

用户要求「先给方案再动手」时，如果把计划当成普通问答，批准与否就没有可执行的含义：模型可以继续写代码，用户的决定也不约束后续动作。

可选做法：

1. 不做 Plan，只做执行加 Todo 进度。
2. 用独立 Planner Agent 产出方案，再把方案交给执行 Agent。
3. 同一个主 Agent 进入只读模式产出方案，由宿主切换可用工具集合并等待用户决定。

## 结论

选 3。`enter_plan_mode` 由宿主收起写类工具，`exit_plan_mode` 提交方案并暂停等待；用户可批准、要求修改或拒绝，分别进入执行、回到只读规划、停止本次实施。批准只对提交的那一版方案有效，方案改变使旧批准失效。Todo、Plan 与审批决定保存在 Message 的结构化 parts 中，由宿主维护当前状态并推送 UI。

## 后果

- Plan 期间只允许读文件、搜索与读取 Skill；Write、Edit、Move、Delete、通用 Bash、发布与 `create_skill` 由执行器拒绝。
- 不新增 Planner Agent，获批后由同一个 Agent 继续，省掉一次交接与一份重复上下文。
- 审批是权限状态，不要求进程常驻；持久化审批记录不代表重启后自动续跑（ADR 0002）。
- Todo 与 Plan 都是核心工具与产品状态，不是 Skill；是否调用由主 agent 判断，宿主不写死「先规划再执行」的流程，只在进入 Plan 后执行权限限制。
- 本决策只排除独立的 Planner Agent，不排除 review subagent（ADR 0013）。
