# 原型 · AI 输出的过程折叠（folded-run）

**这一版要回答的问题是：一轮生成里的「过程」（思考 + 工具调用 + 构建阶段）应该怎么折叠？**

现状是三条重叠的过程展示同时存在：`.build-progress` 阶段条、每条工具调用各自一张卡、`GenerationUsage` 一张用量 `<details>`。目标是照 v0 那种「Worked for 23s」的形态把它们收成一层，正文永远在外面。

## 打开

双击 `index.html` 即可，无外链、无网络请求、不读 localStorage。

或者：

```bash
cd paimeng-ai-code-agent/docs/prototypes/in-progress/folded-run
python3 -m http.server 8000
# http://127.0.0.1:8000/?variant=A
```

## 三个变体（`?variant=`，也可以点底部浮动条或按 ← / →）

| key | 名字 | 结构 |
| --- | --- | --- |
| `A` | 一行折叠组 | 贴 v0：一行 `已生成 23s` + 行数差药丸 + `⋯`，底部一条发丝线；展开后是二级摘要行（「读了 1 个文件、列了目录、联网 1 次，还有 3 项」）→ 逐条步骤 → credits 脚。无卡框，正文在组外。 |
| `B` | 左侧时间线 | 不用卡片壳，改用一条贯穿的竖线把每个步骤串成节点；默认只留**最后两步**，更早的压成一行「＋ 更早的 4 步 · 读了 2 个文件…」。折叠边界是「最近几步」，不是「整组」。 |
| `C` | 摘要行 + 侧栏过程 | 聊天流里只剩一行「已生成 · 7 步 · 23s」，明细整份挪进右侧滑出面板，聊天记录里不再有工具卡。最激进的一版。 |

三者共享同一份演示数据，只有外壳和折叠边界不同——不然没法比较。

## v0 实测（2026-10-31，登录后量出来的）

折叠行是 Radix Accordion（`data-state` + `aria-controls`），量到的值：

| 部位 | 实测值 |
| --- | --- |
| 折叠行按钮 | `min-height: 24px`、13px/16px、`color #4d4d4d`、`border-radius 6px`、`gap 4px`、hover 变 `#171717`、`focus-visible` 蓝环 2px |
| 折叠行容器 | `border-bottom 1px #ebebeb`、`padding-bottom 8px`、`margin-bottom 8px`、`gap 8px` |
| 折叠箭头 | 13px 图标，收起指右、展开指下，`transition: none`（瞬间翻转） |
| 颜色过渡 | 150ms `cubic-bezier(.31,.1,.08,.96)`，只作用在 color/opacity |
| 展开体 | 高度动画 200ms `cubic-bezier(.3,.1,.7,.9)`，`overflow: hidden`，内容 `gap 8px` + `padding-top 8px`，最大高 360px 内部滚动（滚动条隐藏） |
| 行数差药丸 | 高 24px、12px/16px、weight 500、`border 1px #e4e4e7`、圆角 4px、内边距 `0 8px`、`gap 6px`；`+N` `#45a557`、`/` `#c9c9c9`、`-M` `#da2f35` |
| 步骤行 | 13px/21px、`color #8f8f8f`、左侧 13px 图标列（`grid-cols-[min-content_1fr]`） |

| 正文 | 13px/21px（1.615），`#18181b` |
| 组内顺序 | 结果缩略图 → 二级摘要 → 步骤 → `v0 Mini used 0.017 credits` → 时间戳 |

### 因此改掉的三个误读

1. **药丸不是 token**。`+12 / -2`、`+138 / -45`、`+3,997` 都是**行数差**（新增/删除行），v0 的同一张卡片上也会再出现一次。原型现在按 `write` / `edit` 的 part 算 `+新增 / -删除`。
2. **折叠行不是完全无边框**。它没有卡框，但底下有一条发丝线（`#ebebeb`）把这一轮和正文分开。之前那版把边框整个去掉，过白了。
3. **折叠行不是卡片控件**。24px 行高、13px 字、4px 图标间距，是一行文字，不是一块面板。

### 样式：结构照 v0，配色与层次用我们自己的

量完之后真正做的调整：

- **图标自绘**，一套 16px / 1.5px 描边的 inline SVG（思考、目录、读取、写入、修改、搜索、网页、图片、构建）。原来用 `◌ ≡ ▤ ⌕ ✎` 这类 unicode 字形顶替，字重和大小都不受控，混在中文里显脏。
- **层次靠灰度而不是字号**：折叠行 `#5f544c`（7.35:1）、步骤标题 `#6b6058`（6.11:1）、meta 与用时 `#7d6d62`（4.96:1）、脚部同色。v0 全用一个 `#8f8f8f`，中文下会糊成一片。
- **用时单独一列**：右对齐 + `tabular-nums`，和二级摘要行的合计用时同一条竖线。
- **二级摘要缩进 21px**，让它的文字与步骤标题的左边缘对齐。
- **脚部拆成左右两栏**：左边 credits，右边 token，上面一条发丝线。
- **箭头自己画**，收起指右、展开指下，160ms 翻转；步骤行的箭头只在悬停或展开时出现（时间线变体里完全不出现，节点已经在表达它）。
- **`⋯` 悬停才浮现**，避免和一个常驻控件抢注意力。

实测对比度（白底）：折叠行 7.35:1 / 步骤标题 6.11:1 / 二级摘要 4.93:1 / meta 与用时 4.96:1 / 药丸 `+` 5.09:1、`-` 5.16:1。impeccable 检测器 0 warning。

### 有意不一致的地方

- v0 展开体顶部有一张**结果缩略图**；我们有右侧实时预览，不重复放。
- v0 的步骤行不带用时；这里的每行右侧都带用时（本轮明确要求）。
- 字体：v0 用 GeistSans，我们用系统字栈，与生产一致。

## 状态

顶栏的「状态」不放 URL 以外的地方（同时写进 `?state=`），四种：

- `done`：这一轮结束。A 默认收起、B 只留两步、C 只有一行。
- `thinking`：只有一个正在进行的思考块，标题「正在思考」，用时持续递增。
- `running`：思考已结束，最后一步「阶段构建」在跑；思考块显示「已思考 · 0.6s」，只有构建和所属组的用时继续递增。
- `failed`：最后一步构建失败，同时带诊断文案。A 与 B 会把失败那一步默认展开，正文换成失败说明。

## 演示数据声明

- 应用名「田边儿合作社农机预约」、版本号、时间、token 数量、credits 都是编的。
- 工具名与步骤类型（`read` / `listFiles` / `write` / `edit` / `buildPreview` / `webSearch`）取自 `paimeng-ai-code-agent/src/components/chat/tool-call.tsx` 的真实视图类型；阶段名取自 `generation-feedback.ts`。
- 不连模型、不连数据库、不做真实构建。

## 三个变体共有的约定

- **正文永远在外面**。折叠只吃「过程」，不吃回答。
- **生成中自动展开，结束后回到默认**。`thinking` / `running` 时 A 会展开整组与二级摘要，B 显示全部步骤，C 的行变成流式指示；`failed` 时 A 也会展开，并把失败那一步连同诊断一起摊开——错误不该藏在折叠里。
- **头部数字在收起时也可见**：时长 + token 增量。生成中还没有结算，所以 token 与 credits 显示「用量结算中」，不编一个数字出来。

## 本轮确认

- 两套措辞分层：外层过程组说这一轮的地位（`生成中` / `构建中` / `已生成` / `生成失败`，与生产的状态词一致），思考那一行说自己（`正在思考` / `已思考`）。两者不共用一句话，否则会出现「已思考 23s」这种答非所问。
- 思考进行中用「正在思考」，思考结束用「已思考」；工具执行不延长已结束的思考耗时。
- 每层折叠标题都有用时：外层过程组、二级动作摘要、单步思考/工具，以及 B 的「更早步骤」和 C 的过程入口。收起后用时仍可见。
- 摘要层的用时为所含步骤耗时之和；外层为整轮经过时间，两者口径不同。
- 只有一步时不出现二级摘要行（没有可摘要的东西），思考中的样子就是「生成中 1.2s」＋「正在思考 1.2s」两行。
- A 是无边框的：v0 的折叠行没有任何卡片壳，只有一行字 + 缩进的内容。之前那版画了卡框，是和 v0 最大的观感差距。

## 已知上限

- 初始耗时是演示值；活动块各自从自己的初始耗时累加浏览器经过时间，结束块的耗时保持不变。
- `credits` 目前生产里没有数据源（记账只有 token），这一行是在看 v0 截图时顺便带上来的，可以先砍。
- 折叠状态只在内存里：切换变体或刷新就回到默认。生产里如果按消息持久化，需要额外决定存哪里。
- 不看移动端：折叠行为在窄屏是一致的，宽度不是这次的问题。
- A 头部右侧的 `⋯` 只是占位，没有菜单（生产里可以考虑放「用量明细」「复制这一步」）。
- C 的一行摘要必须自己再压一遍（`compactSummaryOf` 只留两项），否则一条横线放不下——这本身就是 C 的成本。
- 写死的耗时按 0.1s 粒度累加，和组头「已思考 · 23s」不会严格相等（差在没算上的模型思考时间）。
