# 单槽位沙箱原型

**THROWAWAY PROTOTYPE：可丢弃，不是生产实现。** 原型放在构建模块旁，未被产品代码引用。

问题：现有电脑能否通过「单个执行槽位 + 模板依赖共享 + 同一次占用内复用容器」完成真实 React / Vue 构建？取消和超时后，是否能销毁整个环境，再让后续请求运行？

## 打开交互原型

双击同目录的 `index.html`。一个自包含文件，不需要服务器、不联网、不持久化。

页面提供自由操作和五组分步场景：串行与复用、取消排队、执行中取消与超时、重启与迟到回调、清理失败。调度状态中的请求均为演示；页面不虚构内存数字。页面下方已内嵌本机缓存命中后的真实报告，也可以选择新实验生成的 `report.json` 替换。

## 运行真实 Docker 实验

在 `paimeng-ai-code-agent/` 下运行：

```bash
npm run prototype:sandbox
```

前提：Node 24、可用的 Docker，以及本机已有 `node:24-alpine` 镜像。原型不会拉取或构建镜像。首次为两个固定模板执行 `npm ci --ignore-scripts`，需要网络，使用 `.env` 的 `BUILD_NPM_REGISTRY`（默认 npm 官方源）；后续命中缓存时不重复安装。

只会创建 `paimeng-prototype-<runId>-*` 容器；使用独立标签识别。实验数据保存在 Git 忽略的 `runtime/sandbox-prototype/`。不访问业务数据库、不连接 Harness、不修改现有 App、模板、预览或 Delivery。

### 实际执行顺序

1. 分别准备 React 与 Vue 的锁定依赖，安装容器串行运行。
2. 同时向内存队列提交 A—F 六个请求。
3. A：在同一个 React 容器中连续执行两次类型检查与 Vite 打包；两次之间修改临时源码。
4. B：独立 Vue 容器完成类型检查与打包。
5. C：排队期间取消，不创建容器。
6. D：模拟命令超时，销毁容器及其子进程。
7. E：模拟运行中取消，销毁容器及其子进程。
8. F：再次创建 React 容器，复用只读依赖并完成构建，检查队列可继续工作。
9. 检查 D / E 的子进程没有延迟写入，且本次实验没有剩余容器。

每个任务容器最多 768 MiB、1 CPU、128 个进程，禁止交换到 swap；根文件系统只读，任务容器断网。只读挂载依赖，源码目录分别可写。Vite 所需 `.vite-temp` 独立挂载临时文件系统，不修改共享依赖。依赖使用宿主机独立目录模拟预装镜像的不可变依赖层，尚未制作正式模板镜像。

### 测量和结论边界

`report.json` 保存每次类型检查与构建的总耗时、排队时间、空闲内存、cgroup 当前内存与历史峰值。`memory.peak` **包含文件缓存**，不同于 Docker stats 扣除部分缓存后的数值；不能把它等同于 Node 堆内存或整机新增占用。容器删除时间计入任务占用槽位的总时长。

实验检查只读依赖不可写、容器没有非 loopback 网卡、工作目录不存在平台 `.env`、Docker socket 未挂载。这些是配置探针，**不是容器逃逸或安全审计证明**。

真实队列仅在一个脚本进程内有效。重启对账、迟到回调和清理失败仅在 HTML 模型演示，不是实测恢复能力。尚未验证 Postgres 跨进程互斥、持久化恢复、沙箱文件工具适配、磁盘配额、gVisor、复杂生成应用和常驻开发服务器。终止脚本或宿主机崩溃后的回收也未实现，不能用于生产。

现阶段验证的是复用**镜像和模板依赖**，以及同一次执行中的容器复用；不让不同 App 复用一个仍存活的可写环境。源码和输出仍按请求隔离。

## 本机实测结论

2026-10-31 完成两轮真实实验，均退出码 0。首次实验 `402d0fbe` 中，React 依赖准备约 7.77 秒、Vue 约 6.06 秒；第二轮 `627d8c33` 命中两份依赖缓存，没有启动安装容器。依赖缓存合计约 430 MiB 磁盘空间。

第二轮结果：

| 请求 | 行为 | 结果 | 类型检查 + 打包 | cgroup 内存峰值 |
| --- | --- | --- | --- | --- |
| A | 同容器两轮 React 构建 | 成功 | 4.07 / 4.20 秒 | 215.2 MiB |
| B | Vue 构建 | 成功 | 4.37 秒 | 231.6 MiB |
| C | 排队期间取消 | 未创建容器 | 不执行 | 不占容器内存 |
| D | 命令超时，销毁容器 | 已超时 | 不执行 | 42.6 MiB |
| E | 执行中取消，销毁容器 | 已取消 | 不执行 | 41.6 MiB |
| F | 后续 React 请求，复用依赖 | 成功 | 4.36 秒 | 209.3 MiB |

任务容器空闲时约 21 MiB。第二轮确认两条延迟写入子进程都实际启动过，容器销毁后未发生延迟写入；队列继续执行成功，最多一个任务容器，结束无剩余实验容器。HTML 五个引导场景已在 Chromium 中完整操作，未发现页面脚本错误，390px 宽度没有页面水平溢出。

**结论：对于仓库当前两个模板，单槽位 + 只读依赖共享 + 同次执行容器复用具有可行性。** 当前证据不支持扩大为任意生成工程的性能或安全保证。没有验证不同 App 共用存活容器，也没有把模型接入生产。

完整原始记录位于 `runtime/sandbox-prototype/<runId>/report.json`，类型检查与 Vite 日志也在同目录。缓存命中报告的测量字段已内嵌 HTML，分享该文件即可查看。
